# mflux-web: local web UI for image generation

## Goal
`mflux-web` serves a browser UI for filling in and running mflux generate commands:
model, prompt, size, steps, seed, LoRA, img2img and so on. It keeps models loaded
between runs. It binds to loopback by default and is secure by default when exposed
beyond it.

## Decisions (agreed)
- **Execution:** in-process, single-worker job queue, model cache keyed by
  `(command, model, model_path, base_model, quantize, lora_paths, lora_scales)`.
  Cache size is 1 by default (`--cache-size N`); evict and `mx.clear_cache()` on switch.
- **Frontend:** hand-written CSS (custom properties, light/dark) + vanilla JS.
  No build step, no Tailwind, no fonts shipped (system font stack). *Changed during
  implementation:* Alpine.js was dropped. The strict CSP (`script-src 'self'`, no inline
  script) would need Alpine's restricted CSP build, and rendering a schema-driven form is
  simpler in plain DOM code. Nothing third-party is vendored.
- **oMLX reuse:** adapt `omlx/admin/auth.py` only, keeping the Apache-2.0 SPDX header,
  plus a `NOTICE` entry. Reimplement the loopback/network helpers from scratch.

## Layout
```
src/mflux/web/
  cli.py        # mflux-web entrypoint: parse, check bind/auth, run uvicorn
  auth.py       # session cookie + key compare (adapted from oMLX, Apache-2.0)
  network.py    # loopback detection, startup refusal rules
  paths.py      # output/model/input path confinement
  schema.py     # mflux-capabilities dump -> form field specs
  adapters.py   # per-command load_model()/generate() seam (phase 1)
  runner.py     # job queue, model cache, callbacks -> SSE events, cancel
  routes.py     # ~15 routes
  templates/    # base.html, index.html, gallery.html, login.html
  static/       # app.css, common.js, generate.js, gallery.js, auth.js
```
Optional extra `mflux[web]`: fastapi, uvicorn, jinja2, itsdangerous, python-multipart.
`mflux-web` fails with a one-line install hint if the extra is missing.

## How the form works
1. `schema.py` calls `build_capabilities()` in-process and caches the result. It maps
   option types to widgets (`bool`→checkbox, `choices`→select, `int`/`float`→number,
   `path`→picker restricted to allowed roots), hides `ignored`/`rejected` options, and
   annotates `conditional` ones. Fields are grouped into Basic (prompt, size, steps,
   seed, guidance), Model, LoRA, Image-to-image and Advanced.
2. On submit, the server rebuilds an argv from the form and parses it with that command's
   own `build_parser()`. This validates exactly like the CLI with no duplicated rules.
   The UI also displays that argv as a copyable equivalent CLI command.
3. The adapter turns the parsed `Namespace` into a cached model plus a
   `generate_image(...)` call.

## Execution seam (the main risk)
Every CLI `main()` currently fuses load + generate. Plan:
- **Phase 1:** `web/adapters.py` holds explicit adapters for text-to-image commands:
  `mflux-generate`, `-flux2`, `-qwen`, `-qwen-2.1`, `-z-image`, `-z-image-turbo`,
  `-krea2`, `-ernie-image(-turbo)`. Each adapter mirrors its CLI's `main()` split into
  `load(args)` / `run(model, args, seed)`. Unadapted commands are listed as
  "CLI only" in the UI.
- **Phase 2 (separate PR, needs maintainer buy-in):** move the split into the CLIs
  themselves so `main()` = `load` + loop `run`, and delete the web adapters. That removes
  the duplication and makes every command web-capable. This follows the repo rule to
  prefer shared abstractions over one-off paths.

## Runner
- One generation at a time (Metal/MLX; parallel runs would OOM). FIFO queue; the UI
  shows queue position.
- Callbacks registered per job: progress (step/total, it/s), optional preview
  (decode latents every N steps, off by default because decoding is expensive), and
  cancel (sets a flag; an in-loop callback raises `StopImageGenerationException`).
- Events stream over SSE at `GET /api/jobs/{id}/events`.
- Output is always saved with `--metadata` JSON so the gallery can reload settings.
- MLX work runs in a dedicated thread; the asyncio loop only relays events.

## Security (defaults)
- Bind `127.0.0.1:8001` by default.
- Non-loopback `--host` **refuses to start** without `--api-key` / `MFLUX_WEB_API_KEY`.
  No flag disables auth off-loopback.
- Loopback with no key: open by default (same as the CLI user). `--require-auth` forces
  login on loopback too.
- First-run key setup page is only reachable when both bind and peer are loopback.
- Session: itsdangerous-signed cookie, `HttpOnly`, `SameSite=Strict`, `Secure` when
  `--tls-cert/--tls-key` are given or `--behind-https`. Secret persisted in
  `~/.config/mflux/web.json` (0600).
- CSRF: every state-changing request must carry a matching `Origin`/`Host` plus an
  `X-MFlux-CSRF` header token from the session.
- Login rate limit: exponential backoff per client IP; failures are logged by key
  fingerprint only.
- **Path confinement** (the web-specific hole):
  - outputs go only under `--output-dir` (default `~/AI/mflux-web/outputs`). The form
    takes a filename template, not a path, and the resolved path must stay under the root.
  - `--model` / `--model-path` / LoRA paths: HF names or paths under
    `--models-dir` (repeatable) only.
  - uploaded input images (img2img, edit) go to a temp dir under output-dir, get
    size-capped, and are verified with PIL.
- Security headers: CSP `default-src 'self'` (no inline script or style),
  `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.
- TLS: optional `--tls-cert/--tls-key`. The README documents Tailscale Serve / Caddy as
  the recommended way to expose the UI.

## Routes
Pages: `GET /`, `GET /gallery`, `GET /login`.

`GET /api/capabilities`, `GET /api/models`, `POST /api/uploads`,

## Out of scope (v1)
Training, `mflux-save`, upscalers, controlnet/fill/in-context UIs (phase 2), i18n,
multi-user accounts, HF download manager.

## Implementation notes (2026-09-26)
- Version `0.20.0+web` (PEP 440 local label); git tag `v0.20.0-web` on the fork.
- The CLI `MemorySaver` deletes text encoders after each run, so it is never registered on
  cached models. `--low-ram` jobs run uncached with the CLI callbacks, then free the model.
- `parse_args()` reads `sys.argv` and sets `GeneratedImage.model_path` /
  `ImageUtil.embed_metadata_enabled`. Parsing and saving run under `Invocation.LOCK`,
  and validation parses restore both flags afterwards.
- Security review (LFI / injection): no shell or subprocess in `mflux.web`. Every path
  goes through `PathGuard` with symlinks resolved. Numbers must be finite and bounded
  (JSON allows NaN/Infinity). Upload size is checked before decoding. Requests carrying
  forwarding headers are refused unless auth is on. `shlex.join` output round-trips to
  the exact argv. All of this is pinned in `tests/web/test_security.py`.
- Phase-2 guardrail: `WeightLoader._load_torch_checkpoint` uses
  `torch.load(weights_only=False)` (Depth Pro, fixed Apple URL). Before depth commands join
  the web UI, they must not accept user-chosen weights.
